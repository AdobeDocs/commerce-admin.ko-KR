# Adobe Commerce B2B 고정 문제(v1.5.4-alpha1)

## B2B v1.5.4-alpha1

*2026년 10월 13일*

Adobe Commerce B2B 1.5.4-alpha1 코드에서 23가지 문제가 수정되었습니다. 이 릴리스에 포함된 해결된 문제의 하위 집합은 아래에 설명되어 있습니다.

### 관리자 UI

#### 백 엔드 견적의 업데이트 가격 이후에 [B2B] 번들 제품 수량이 유지되지 않음

구성 대화 상자를 통해 구성을 변경한 후 관리 협상 가능 견적의 번들 항목 수량이 그리드에서 수량을 편집한 후 이전 값으로 되돌려지는 문제를 해결했습니다.

_ACP2E-5005_

### B2B

#### [B2B] 견적 세부 정보 페이지(상점 및 관리자)에서 관련 제품을 카탈로그에서 삭제하면 항목/제품 정보가 손실됩니다

판매가 불가능한 제품이 확정된 협상 가능 견적에서 사라지는 문제가 수정되었습니다.

_ACP2E-4680_

#### 백엔드에서 견적을 보낸 후 번들 제품 수량이 올바르게 업데이트되지 않음

관리 패널에서 협상 가능한 견적을 재구성할 때 번들 제품 옵션 수량이 업데이트되지 않던 문제를 수정했습니다. 이전에는 구성 버튼을 통해 번들 옵션 수량에 대한 변경 사항이 자동으로 삭제되었습니다.

_ACP2E-4801_

#### [CLOUD] [B2B] 관리 회사 그리드로 인해 높은 MySQL CPU — 상관 관계가 있는 company_type/COUNT 쿼리가 발생합니다.

관리 회사 그리드(고객 → 회사)로 인해 높은 MySQL CPU 사용 및 장기 실행 데이터베이스 세션이 발생하는 문제를 해결했습니다. 이전에는 각 행에 대한 회사 유형(상위/1차 하위 구성요소/회사)을 결정하려면 회사 행당 한 번 실행된 company_relation 테이블에 대해 상관 관계가 있는 하위 쿼리가 필요하므로 규모에 따라 목록 및 총 개수 쿼리가 모두 O(N²)됩니다. 이 수정 사항은 데이터 세트 크기에 관계없이 한 번 실행되는 사전 집계된 단일 JOIN으로 대체합니다.

_ACP2E-4846_

#### 계정에서 결제(B2B) - 보류 중인 주문에 대한 주문 편집 버튼이 누락되고 COD에 표시됨

이제 결제 시 주문 버튼을 사용할 수 있습니다. 이전에는 주문이 보류 중인 상태에서 결제 시 주문한 주문을 편집할 수 없었습니다

_ACP2E-4877_

#### 다중 회사 수퍼 유저가 있는 B2B 회사를 저장하는 PHP 시간 제한

B2B 회사를 저장하거나 회사의 수퍼 유저 페이지를 관리자에 로드해도 회사의 수퍼 유저가 매우 많은 수의 회사에 할당될 때 PHP 최대 실행 시간을 더 이상 초과하지 않습니다.

_ACP2E-4967_

#### [ON-PREM] 협상 가능한 견적이 예상대로 업데이트되지 않음

활성 협상 가능 견적에 있는 제품이 삭제될 때 협상 가능 견적이 업데이트되지 않던 문제를 수정했습니다.

_ACP2E-5001_

#### 변동성 &#39;계정입금&#39; 추가 수표

개인(B2C) 고객이 결제 시 B2B 회사 멤버만 사용할 수 있는 결제 방식인 &#39;계정입금&#39;을 선택할 수 있었던 문제를 수정했습니다. 이전에는 이러한 고객이 &quot;결제 방법을 사용할 수 없음&quot; 오류를 수신하는 대신 계정에서 결제를 진행할 수 있도록 잘못 허용되었습니다.

_ACP2E-5013_

#### 공유 카탈로그 마법사 저장 작업은 공유 카탈로그의 가격 구조를 지웁니다

공유 카탈로그 마법사의 저장 작업이 공유 카탈로그 저장의 가격 구조를 지우는 문제를 해결했습니다

_ACP2E-5015_

#### GraphQL customer.role은 회사가 없는 B2C 고객에 대해 &quot;내부 서버 오류&quot;를 반환합니다.

GraphQL을 통해 고객 { role {...} }을(를) 쿼리하면 회사에 할당되지 않은 B2C 고객에 대해 &quot;내부 서버 오류&quot;가 반환되는 문제가 해결되었습니다. 이전에는 엄격한 정수 형식 힌트가 있는 메서드에 null 회사 ID가 전달되었으므로 이 쿼리가 PHP TypeError를 트리거했습니다.

_ACP2E-5017_

#### 옵션 수량이 백엔드 견적에 업데이트되면 [B2B] 번들 제품 항목 할인이 적용되지 않습니다.

백엔드 견적 관리자의 동적 가격 번들 제품에 적용된 항목 수준 할인이 소계 또는 소계에 반영되지 않던 문제를 수정했습니다(제외). 세금) 구성 대화 상자를 통해 번들의 옵션 수량이 업데이트된 경우 열. 이전에는 할인율이 할인 열에 나타났지만 인용된 소계를 감소시키지는 않았다.

_ACP2E-5034_

#### 모든 페이지 탐색에서 구매요청 섹션이 다시 로드됨

구매요청 섹션이 모든 제품 및 범주 페이지 탐색에서 불필요한 AJAX 재로드를 트리거하는 문제를 해결했습니다. 이전에는 변경하지 않았더라도 비어 있지 않은 구매요청 목록 데이터가 있는 고객에 대해 페이지를 로드할 때마다 섹션이 다시 로드되었습니다.

_ACP2E-5037_

#### 회사 주소에 지역 데이터가 없는 경우 [B2B] 오류가 발생합니다.

주소가 영역 없이 저장된 후 회사 주소의 영역이 해당 국가에 추가되면 회사 프로필 페이지 및 관리자 고객 편집 페이지에 오류가 표시되는 문제가 수정되었습니다. 이제 오류가 발생하지 않고 주소가 저장된 영역 텍스트로 올바르게 대체됩니다.

_ACP2E-5092_

#### 영어 이외의 로케일로 관리자가 업데이트되면 크레딧 제한이 재설정됩니다.

관리자의 로케일이 기본 로케일과 다를 때 B2B 회사의 세부 정보를 편집하면 의도하지 않게 구성된 크레딧 제한이 0으로 재설정될 수 있는 문제를 해결했습니다. 이제 신용 한도가 명시적으로 수정되지 않는 한 올바르게 유지됩니다.

_ACP2E-5127_

#### [CLOUD] 웹 사이트 제한 관리자는 user_id가 액세스할 수 없는 고객 entity_id와 충돌하는 경우 고객을 삭제할 수 없습니다.

이전에는 웹 사이트 제한 관리자가 고객을 삭제하려고 할 때 시스템의 권한 확인 플러그인이 관리자의 사용자 ID와 비교되었습니다
관리자 사용자 ID가 발생한 경우, 실제 사용자가 고객인지 확인하지 않고 회사 계층 제한을 적용하는 고객 엔티티 ID
관리자가 액세스할 수 없는 웹 사이트에서 관련 없는 고객의 엔티티 ID와 일치하도록 플러그인은 액세스할 수 없는 고객 레코드를 로드하려고 했습니다
관리자가 삭제되는 고객에 대한 유효한 권한이 있어도 &quot;추가 권한이 필요합니다&quot; 오류가 발생하여 삭제하지 못했습니다. 해결되었습니다.
조건을 추가하여 실제 사용자가 고객인 경우에만 고객 ID 비교가 실행되도록 합니다. 즉, 관리자가 시작한 삭제는 이제 완전히 검사를 우회합니다. 제한된 관리자는 관련이 없고 액세스할 수 없는 고객 레코드에 의해 차단되지 않고 할당된 웹 사이트 내에서 고객을 다시 한 번 삭제할 수 있습니다

_ACP2E-5146_

#### B2B 주문이 관리 판매 주문에 잘못된 회사 이름을 표시합니다.

사용자가 여러 회사에 할당되었을 때 관리 판매 주문의 B2B 구매 발주에 대해 잘못된 회사 이름이 표시되던 문제를 수정했습니다.
이제 주문과 연계된 회사를 기준으로 회사 이름이 올바르게 표시됩니다.

_B2B-4656_

### B2B, 장바구니 및 체크아웃

#### [ON PREM] [B2B] .CSV 확장명으로 끝나는 이진 파일을 업로드하려고 하면 빠른 순서 업로더가 중지됩니다.

빠른 주문 파일 업로더가 바이너리를 포함하여 .csv 확장명으로 이름이 변경된 파일을 수락하는 문제가 해결되었습니다. 이전에는 MIME 유형 또는 콘텐츠 유효성 검사가 수행되지 않았으므로 CSV가 아닌 파일(예: 실행 파일)을 유효한 SKU/QTY 목록인 것처럼 업로드하고 처리할 수 있었습니다.

_ACP2E-5212_

### B2B, GraphQL

#### 구매요청 목록 GQL 총 개수 부정확함

구매요청 목록 GraphQL 질의가 질의 기준과 일치하는 총 구매요청 목록 개체 수 대신 현재 페이지의 품목 수만 반영하는 잘못된 total_count 값을 반환한 경우 문제를 해결했습니다.

_ACP2E-4799_

### B2B, 주문

#### 59M+ 견적 테이블 정리에 대한 도움말(sales_clean_quotes를 실행할 수 없음)

큰 따옴표 테이블이 있는 인스턴스에서 `sales_clean_quotes` cron 작업이 시간 초과되는 문제를 해결했습니다. 이전에는 정리 쿼리가 `negotiable_quote` 테이블에서 모든 열을 불필요하게 선택했기 때문에 MySQL이 수백만 행에 대해 전체 파일 정렬을 수행했으며, PHP 모델 계층을 통해 각 견적이 개별적으로 삭제되어 성능 비용이 증가했습니다.

_ACP2E-4891 - [GitHub 코드 기여도](https://github.com/magento/magento2/commit/b63925d9)_

### B2B, 성능

#### [CLOUD] ACSD-70033 후속 작업 : magento_catalogpermissions_index_product 테이블의 교착 상태. 연속

이전에는, 공유 카탈로그가 활성화된 상태에서 카탈로그 권한을 리인덱싱하면 교착 상태 오류가 발생하여 리인덱싱이 실패할 수 있었습니다. 이제 여러 인덱서 프로세스가 동시에 실행되는 경우에도 리인덱싱이 성공적으로 완료됩니다.

_ACP2E-4844_

### 콘텐츠

#### 다른 웹 사이트용으로 만들어진 CMS 페이지의 프론트엔드에 잘못된 페이지가 표시됨

이전에는 웹 사이트 제한 랜딩 페이지 캐시 키의 범위가 웹 사이트별로 지정되지 않은 다중 웹 사이트 설정에서 잘못된 CMS 페이지가 보조 웹 사이트 상점 첫 화면에서 제공되었습니다. 이제 WebsiteRestriction/Controller/Index/Stub.php의 캐시 키에 저장소 관리자를 통해 확인된 현재 웹 사이트 ID가 올바르게 포함됩니다.

_ACP2E-4593_

### 프레임워크

#### [B2B] 구매 주문이 ActiveMQ를 사용하여 판매 주문으로 자동 전환되지 않음

ActiveMQ를 STOMP 프로토콜과 함께 사용할 때 cron으로 시작된 소비자가 메시지를 처리하지 않던 문제를 수정했습니다. 그 결과 자동 승인된 구매 발주는 판매 주문으로 전환되지 않았습니다. 이제 STOMP 대기열에 대한 메시지 처리가 보다 안정적이고 DB 및 AMQP 대기열 구현과 일관됩니다.

### 설치 및 관리

#### [클라우드] 오래된 기존 ISO 하위 분류 코드 수정

ISO 3166-2 표준에 맞게 13개 국가의 지역 코드가 업데이트되었습니다. 이전에는 일부 지역 코드가 표준과 일치하지 않아 서드파티 통합 및 국제 규정 준수에 문제가 발생할 수 있었습니다. 벨기에, 콜롬비아, 스페인, 프랑스, 이탈리아, 라트비아의 새로운 지역이 추가되었다. 오스트리아, 콜롬비아, 코스타리카, 독일, 에스토니아, 스페인, 핀란드, 프랑스, 인도, 아이슬란드 및 라트비아의 지역 코드가 업데이트되었습니다.
